# Rangeset「综合排序」研究与方案（2026-11-21，UTC+8）

## 结论先行

- **推荐 v1：分层规则 + 品牌按占比穿插。** 只做排序，不打分，也不用加权总分。
- **分层**（硬规则，先比层级）：
  - **A 层**：官网有货，卡片 4 项至少 3 项有值，且近两季发布。
  - **B 层**：官网有货，卡片 4 项至少 3 项有值，但发布季较早或未公布。
  - **C 层**：卡片信息不全（≤2 项有值）。
  - **D 层**：官网售罄，或在售尺码少于一半。
- **同层内**：各品牌按其在本类中的商品占比交错出现，用平滑加权轮询。同一品牌内按发布季从新到旧排，再按款式族、名称排。
- **缺失值一律不惩罚**：未公布发布季归 B 层（中间层，不是垫底）；没有库存数据视为不降级；"不适用"（N/A）算作有值。
- **v2（有了真实用户数据之后）**：同层内改用"Rangeset 站内关注度"，即 28 天内的比较加入次数和详情浏览次数，经过平滑处理。层级规则保持不变。
- **为什么不是之前那版（完整度 → 新季 → 价格升序）**：
  - 完整度几乎拉不开差距：v1.5.0 卡片 4 项填充率分别为 99.5%、99.8%、97.6%、94.0%。
  - "价格升序"会让列表系统性偏向便宜货，Baymard 实测这种默认排序会误导用户。
  - 那版也没有处理多品牌混排的公平问题。

### 学术与业界依据

- **Baymard（默认排序）**：默认排序应是"基于多样性的 Relevance"。
  - 类目的主要子类型都应出现在前约 20 个（桌面端）或前约 10 个（移动端）商品里。
  - 简单实现：以畅销排序为底，占比超过 10% 的子类型保证进入前 20。
  - 命名：用 "Relevance" 或 "Featured"，不要叫 "Popular"，用户会把 Popular 理解为纯销量。
  - 来源：baymard.com/research-articles/default-sort-type
- **Baymard（避免字母序）**：测试中几乎没有用户主动按字母排序，并建议多数站点避免字母序。Rangeset 当前默认正是名称 A–Z（`catalog-browser.tsx` 中 `sort ?? "name"`）。
  - 用户期待的 4 种基础排序：价格、评分、畅销、最新。
  - 品类特有排序同样有价值，Baymard 原文举例"冬季夹克按重量排"。
  - 来源：baymard.com/research-articles/essential-sort-types
- **位置偏差**：排在前面的结果会被不成比例地点击，即使相关性更差。因此默认排序本身就是一次强编辑行为，必须中立、可解释。
  - Joachims 等，SIGIR 2005
  - Craswell 等，WSDM 2008
- **马太效应**：一旦把热度当作排序依据，早期的随机优势会被放大。
  - Salganik、Dodds、Watts，Science 2006，MusicLab 实验
  - 应对：热度信号需要平滑和时间衰减，并给新品曝光。另见 Evan Miller《How Not To Sort By Average Rating》（小样本应取置信下界）。
- **监管**：
  - 欧盟 Omnibus 指令（2019/2161）和 P2B 条例（2019/1150）第 5 条要求披露决定排序的主要参数。
  - 中国《电子商务法》第 18 条要求同时提供不针对个人特征的选项，第 40 条要求竞价排名标明"广告"。
  - 《互联网信息服务算法推荐管理规定》要求公示算法基本原理。
  - 结论：一句话公开规则不只是姿态，也合规。

## 2. 关键结论

1. **业界真正的"综合"几乎都以行为热度为核心**：懂车帝热度、汽车之家关注、END 近期下单、PCPartPicker 热门、Zalando、淘宝、京东、Amazon，而且基本都不公开权重。Rangeset 目前**没有任何站内行为数据**：
   - 仓库没有接入任何分析 SDK。
   - PostHog 只有一个 Default project，过去 90 天的事件全部来自 gyo.one 和 127.0.0.1，没有 rangeset。
   - 所以现在硬做"热度"等于编造。
2. **公开又诚实的做法有两类**：
   - "新品优先"：SSENSE、GSMArena。
   - "公开分桶"：Zalando 把高退货、尺码不全、发货慢的商品放进下层桶，桶内再排序。
   - 这两类都能一句话讲清楚，适合我们。
3. **"规格总分"是反面教材**（Versus 式）：权重任意，看起来很精确其实不精确。OGL 和 RTINGS 能打总分，是因为它们自己买来实测，我们没有实测数据。
4. **多品牌混排必须主动防止单一品牌霸屏**。Baymard 要求前 20 个体现多样性，Zalando 的算法也显式考虑多样性。

## 5. 推荐方案：综合排序 v1（精确定义）

**作用域**：当前筛选结果。按类目时就在类目内；"全部"页面同样适用，此时多样性按类目和品牌两级处理。

### 5.1 分层（tier，小的排前）

对每个商品先计算三个布尔值：

- `stock_low`：**已知**官网在售 SKU（尺码×颜色）中有货比例 < 50%，含 0%。没有库存数据记为 false。
- `info_low`：卡片 4 项中"有值"的项数 ≤ 2。"有值"包括已公布的值和 N/A（不适用）；"— 未公布"和待审核不算有值。
- `recent`：已知官方发布季属于**最近两季**。以当前日期定：2026-11 时为 FW26 和 SS26。季的定义是 SS 对应 1–6 月，FW 对应 7–12 月。发布季未知记为 false。

```
tier = stock_low ? 4 : info_low ? 3 : recent ? 1 : 2
```

多个降级条件同时满足时取最低层（与 Zalando 一致）。按当前数据模拟（库存与发布季两项；信息不全的商品极少），保暖夹克 81 款分为 A 20 / B 55 / D 6，硬壳 113 款分为 A 56 / B 53 / D 4。

### 5.2 层内：品牌按占比交错（平滑加权轮询，确定性）

- 设本层品牌 b 的商品数为 n_b，每个品牌维护一个计数器 `c_b = 0`。
- 权重 n_b 取该品牌在本层的初始商品数，N = Σn_b。每输出一个位置：所有剩余品牌执行 `c_b += n_b`，选出 c_b 最大的品牌（并列时按品牌 slug 字母序），输出该品牌队列的队首，然后令 `c_b -= N`。某品牌出完即移出，N 相应减去它的 n_b。
- 效果：每个品牌在前 24 个中的占比约等于它在本层的占比。小品牌至少能尽早出现一次，大品牌不会连续霸屏。
- 只有一个品牌时（现在的状态），该步骤自然退化为品牌内顺序，对现网零风险。

### 5.3 品牌内队列顺序

1. 发布季从新到旧（未知发布季排在本品牌已知发布季之后）。
2. 同季内按款式族（`analytics_family`）聚在一起，男款、女款相邻，方便比较。
3. 款式族之间、族内都按名称 A–Z 排，保证确定性。

### 5.4 多样性护栏（Baymard，v1.1 可选）

- 若某个 `product_type`（如 vest、parka）在当前列表中占比 ≥10%，保证它至少有 1 款出现在前 24 个（移动端前 12 个）。
- 实现方式：把它的第一款提前到第 24 位。

### 5.5 缺失值规则（汇总）

- 发布季未知：不进 A 层，进 B 层（中间层，**不垫底**）。
- 无库存数据：不降级。
- 卡片项未公布：只有 ≥3 项未公布才降到 C 层。
- 任何字段都不会被当作 0 参与比较。

### 5.6 新品牌冷启动

- 新品牌第一天就进入 A、B、C 层中按事实对应的那一层，并按其**本层占比**获得交错曝光，不用等积累数据。
- 如果新品牌不公布发布季：先在 B 层，等其官网出现明确的季或年份字段后再进 A 层。之后可以用 Rangeset 首次发现时间做辅助，但前提是**首爬之后才出现的新 SKU**，首爬当天全部商品都不算新。

### 5.7 v2：接入站内关注度（数据达标后）

- **前提**：先埋点，记录 `product_view`、`compare_add`、`list_impression`（含位置）。
- **层内排序**：分层规则和品牌占比交错都不变，只把"品牌内队列顺序"第 1 键替换为平滑关注度：
  - `attention = (compare_add_28d + 2·product_view_28d/10 + α·prior) / (impressions_28d + β)`
  - 初始建议 α=β=类目中位数；参数需要上线后调校，**不是定论**。
  - 曝光数用于抵消位置偏差。
  - 新品前 14 天使用类目先验，避免马太效应。
- **启用门槛**：类目 28 天详情浏览量达到一定数量（例如 ≥500，需按实际流量再定）才启用，否则回落到 v1。
- **命名**：仍叫"综合排序"，提示文案加一句"站内关注度"。

## 6. 提示文案（"?" 里一句话）

- **zh**：综合排序：官网有货、卡片参数齐全、近两季发布的优先；同组内各品牌按占比穿插。不收费、不打分、不看品牌。

命名建议：
- zh 用"综合排序"（用户指定）。
- en 用 "Featured"：Baymard 建议用 Relevance 或 Featured，不用 Popular。
- ja 用「おすすめ順」：Amazon.co.jp 等日本电商的常用叫法。

## 7. 需要的数据与改动

1. 从 `product_raw.payload` 取出 `origYear` 和 `origSeason`，归一成 `release_season`（如 `2026-FW`），存入 listing 投影。暂不需要改表结构，可以在 `lib/catalog.ts` 的投影里读取。

   - 缺失发布季的商品进 B 层而不是 D 层

## v1.6.0 实现记录

综合排序在目录按品类、性别、产品线、款式、防护类型、系列和搜索缩小结果后执行，然后分页。已有的名称、价格和重量排序继续可用。默认综合排序省略 URL 中的 `sort`，显式选择其他顺序会记录到 URL。

| 层 | 进入条件 |
| --- | --- |
| A | 卡片至少三项有值，发布季属于当前结果中最新的两个不同已知季，库存条件未触发 D |
| B | 卡片至少三项有值，发布季较早或未知，库存条件未触发 D |
